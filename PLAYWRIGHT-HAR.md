# Recording and replaying Open Library with HAR files

`/search` talks to a live third-party API: the browser calls [`searchOpenLibrary`](./src/lib/open-library.ts), which `fetch`es `https://openlibrary.org/search.json`. That catalog changes, rate-limits, and can time out (the client aborts after 4 seconds). A Playwright spec that asserts a specific title like "The Sun Also Rises" is therefore only stable if the Open Library response is frozen.

A [HAR](http://www.softwareishard.com/blog/har-12-spec) (HTTP Archive) is that freeze: a JSON log of request URLs, methods, headers, and response bodies. Playwright can **record** those calls into a `.har` file and later **replay** them so the test never hits the real catalog.

This only works because search runs in the **browser**. Playwright's `page.routeFromHAR` intercepts the page's network, not Node.js `fetch` on the SvelteKit server. Same-origin calls such as `/api/shelf/lookup` are intentionally left alone.

## The spec that uses it

The only current HAR consumer is [`tests/recording.spec.ts`](./tests/recording.spec.ts):

```ts
test.use({
	serviceWorkers: 'block',
	storageState: './playwright/.authentication/user.json'
});

test('test', async ({ page }) => {
	await page.routeFromHAR('../playwright/recordings/openLibrary.har', {
		url: '**/openlibrary.org/**',
		update: true
	});
	await page.goto('/search');
	await page.getByRole('textbox', { name: 'Search by title, author, or' }).fill('hemingway');
	await page.getByRole('button', { name: 'Search' }).click();

	await expect(page.getByRole('heading', { name: 'The Sun Also Rises' })).toBeVisible();
});
```

That file started as a Playwright codegen recording of the `/search` flow. [`LEFTHOOK.md`](./LEFTHOOK.md) covers how the first commit of it failed the pre-commit gate and what was fixed.

`/search` is a protected route, so the spec also needs a saved session. That file is generated by the `setup` project — see [`PLAYWRIGHT-AUTH.md`](./PLAYWRIGHT-AUTH.md).

## What each option is doing

### `serviceWorkers: 'block'`

Playwright will **not** serve requests that a service worker intercepted from a HAR. Blocking service workers is the documented requirement for HAR routing (and for `page.route` in general). Without it, Open Library fetches can skip the HAR entirely and the test talks to the live API again.

### `url: '**/openlibrary.org/**'`

Only requests whose URL matches that glob are recorded or replayed. Everything else — the SvelteKit document, `/api/shelf`, static assets — still hits the real app. If the glob is omitted, Playwright tries to serve **every** request from the HAR, including the app itself.

The glob matches the hardcoded client base URL in `src/lib/open-library.ts` (`https://openlibrary.org`). Changing that origin without updating the glob will miss the traffic.

### `update: true` vs replay

`page.routeFromHAR` is one API with two modes:

| `update`          | What happens                                                                                                                                     | When to use it                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| `true`            | Live Open Library calls are made. Matching entries are written into the HAR when the browser context closes.                                     | First capture, or a deliberate refresh after the API contract changes. |
| omitted / `false` | Matching requests are fulfilled from the HAR. Nothing is written. A request with no HAR entry is **aborted** (`notFound` defaults to `'abort'`). | Day-to-day runs and CI.                                                |

The intended workflow is:

1. Run the spec once with `update: true` so Playwright creates `openLibrary.har`.
2. Inspect the file (HARs can contain cookies and other sensitive headers).
3. Commit it.
4. Remove `update: true` (or set `update: false`) so later runs replay instead of hitting Open Library.

Right now the spec still has `update: true`. That means every `npm test` run that includes this spec talks to live Open Library and rewrites the HAR. Replay is not locked in yet.

### Where the `.har` file lives

The path in the spec is `'../playwright/recordings/openLibrary.har'`. Playwright resolves a relative HAR path against the **current working directory** (the repo root when you run `npm test`), not against the spec file. From the repo root, `../playwright/recordings/` walks _out_ of this repository.

The storage-state file next to it uses a CWD-relative path (`playwright/.authentication/user.json` in `auth.setup.ts`). A HAR path that matches that convention is:

```ts
import path from 'node:path';

const openLibraryHar = path.resolve('playwright/recordings/openLibrary.har');

await page.routeFromHAR(openLibraryHar, {
	url: '**/openlibrary.org/**'
});
```

`playwright/recordings/` is not gitignored (only `playwright/.authentication/` is). A committed HAR belongs in source control so CI can replay without the live catalog. Do not commit a HAR you have not opened — it is a dump of real HTTP traffic.

No `openLibrary.har` is in the tree today. The first record pass has to create it.

## Regenerating the HAR

With `update: true` still in the spec, a normal test run records:

```sh
npx playwright test tests/recording.spec.ts
```

That requires:

- the `gerome@test.com` account (see [`PLAYWRIGHT-AUTH.md`](./PLAYWRIGHT-AUTH.md))
- network access to `https://openlibrary.org`
- a search for `hemingway` that still returns a heading "The Sun Also Rises"

After the HAR exists, drop `update: true` and keep the assertion. Do **not** re-record a HAR just to make a failing test pass — if replay no longer matches, the app's request (URL, query string, method) changed and that change is the thing to investigate. HAR matching is strict on URL and method; POST bodies are matched strictly too.

To record from the Playwright CLI instead of the spec:

```sh
npx playwright open --save-har=playwright/recordings/openLibrary.har --save-har-glob="**/openlibrary.org/**" http://127.0.0.1:4173/search
```

That captures whatever the open browser does. The spec's `routeFromHAR(..., { update: true })` path is the one this repo actually uses.

## What this does not mock

- **Server-side Open Library calls.** If search ever moved into a `+page.server.ts` load function, `page.routeFromHAR` would not see those requests. Mock at the app boundary instead, or keep the client fetch.
- **Shelf APIs.** `/api/shelf` and `/api/shelf/lookup` are same-origin and outside the glob, so add-to-shelf still hits the real database.
- **A different query.** Replay returns the recorded `hemingway` payload. Searching for another title against a `hemingway`-only HAR will abort that request (default `notFound: 'abort'`) and the UI will look empty.

`notFound: 'fallback'` would send unmatched Open Library URLs to the live network. This spec does not set `notFound`, so unmatched calls abort.
